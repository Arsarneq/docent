# Troubleshooting — both platforms

What to check when Docent refuses, halts, or drops something. This is an index by symptom: each entry names a symptom as the platform shows it and routes to the document that owns the behavior: the user guides ([extension](extension.md), [desktop](desktop-windows.md)) or the format, protocol, and architecture docs each row names. Each row summarizes the owning rule so you can recognize the symptom. The owning document holds the authoritative statement, and when a rule changes there, the matching row here changes with it. Homing this index in the platform, sync, and format areas keeps it in a change's disposition view.

## Import and export

Both platforms run the same shared import acceptance ([Shared Core](../architecture/system/shared-core.md#the-parity-rule)). The [extension guide's Import section](extension.md#import) documents the checks.

| Symptom                                                      | What happened                                                                                                                                                                    | Where the rules live                                                                                                        |
| ------------------------------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------- |
| "Could not read file — make sure it is a valid .docent.json" | The file did not parse as JSON.                                                                                                                                                  | [Extension guide — Import](extension.md#import)                                                                             |
| "Import failed: file does not match the Docent format."      | The file failed the ingestion bounds (at most 10 MiB of JSON, nested at most 64 levels) or schema validation, including the `docent_format` version stamp. Nothing was imported. | [Session Format — Import acceptance](../technical/session-format.md#import-acceptance)                                      |
| A file that used to import is rejected after updating Docent | The version-stamp gate: by design, a schema version bump stops previously exported files from importing. Pin the producing version, or re-export from the current one.           | [Session Format — Schema version pinning](../technical/session-format.md#schema-version-pinning)                            |
| Importing a project you already have produced a second one   | By design: an import never overwrites or merges. The copy gets a new identity and a " (copy)" name suffix.                                                                       | [Extension guide — Import](extension.md#import)                                                                             |
| Desktop: the import or export dialog was cancelled           | Not an error: canceling the native open dialog imports nothing; canceling the native save dialog writes nothing.                                                                 | [Application shell — command surface](../architecture/application/desktop/windows/application-shell.md#the-command-surface) |
| Extension: looking for a file dialog                         | The extension uses the browser's flows: **Export** downloads the file, **Import** opens a file picker on the Projects list.                                                      | [Extension guide — Export](extension.md#export) / [Import](extension.md#import)                                             |

## Send (dispatch)

| Symptom                                                   | What happened                                                                                                                                                                                                                  | Where the rules live                                                                                                                       |
| --------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------ |
| **Send** is disabled                                      | No endpoint is configured, or the open project has no recording with at least one active step.                                                                                                                                 | [Extension guide — Send](extension.md#send); [Dispatch — send eligibility](../api/dispatch.md#send-eligibility-and-the-post-send-cooldown) |
| The endpoint URL is refused when saving Settings          | The save-time URL policy rejected it. The scheme must be `http://`/`https://`, and the URL must have no embedded credentials and no link-local IPv4 address. `https://` is required alongside an API key, except for loopback. | [Dispatch — endpoint URL policy](../api/dispatch.md#endpoint-url-policy)                                                                   |
| **Send** is disabled right after a send, with a countdown | The 5-second post-send cooldown, a guard against rapid resends. A failed send starts no cooldown.                                                                                                                              | [Dispatch — post-send cooldown](../api/dispatch.md#send-eligibility-and-the-post-send-cooldown)                                            |
| A send fails after several attempts                       | Transient failures (network error, timeout, `429`, `5xx`) are retried up to three times, then the last error is shown. Any other status fails at once and is shown.                                                            | [Dispatch — retries](../api/dispatch.md#retries-and-duplicate-delivery) / [response handling](../api/dispatch.md#response-handling)        |
| A send is rejected before anything is sent (size)         | The payload exceeded the 50 MiB outbound bound. Send recordings individually.                                                                                                                                                  | [Dispatch — size bounds](../api/dispatch.md#size-bounds)                                                                                   |

## Sync

The [extension guide's Sync section](extension.md#sync) documents the sync controls and messages once, and the [desktop guide](desktop-windows.md#sync) adopts it.

| Symptom                                      | What happened                                                                                                                                                                                                                                                                                                                                                                                                                                | Where the rules live                                                                  |
| -------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------- |
| A sync halted with a message                 | Each of the four halt messages (recording in progress, uncommitted actions, the protective no-changes halt, the authentication halt) says what to do next.                                                                                                                                                                                                                                                                                   | [Extension guide — What a sync does](extension.md#what-a-sync-does)                   |
| Auto-sync turned itself off                  | An authentication failure during any sync disables Auto-sync. Fix the API key, then test the connection again to re-enable it.                                                                                                                                                                                                                                                                                                               | [Extension guide — Auto-sync](extension.md#auto-sync)                                 |
| The Auto-sync toggle is disabled             | It needs a configured sync server and a connection test passed against the current settings. Saving changed settings invalidates the previous test.                                                                                                                                                                                                                                                                                          | [Extension guide — Configure the sync server](extension.md#configure-the-sync-server) |
| The connection test failed                   | The status line tells rejected credentials apart from an unreachable server, each with its remedy.                                                                                                                                                                                                                                                                                                                                           | [Extension guide — Test the connection](extension.md#test-the-connection)             |
| Rows carry **Review** or **Conflict** badges | Review: the server changed something you have not touched. Conflict: the same item changed on both sides. A project whose name and metadata this client and the server have not yet agreed on counts as changed, so its deletion on one side is a conflict ([SP-11](../api/sync-protocol.md#what-causes-a-conflict-that-must-be-resolved)). A rolled-up badge on a project row opens the project; any other badge opens its resolution view. | [Extension guide — Attention badges](extension.md#attention-badges)                   |
| The sync summary reports skipped projects    | Projects whose format stamp does not match your platform or schema version are skipped, never merged, and reported with the reason.                                                                                                                                                                                                                                                                                                          | [Extension guide — What a sync does](extension.md#what-a-sync-does)                   |

## Capture

| Symptom                                                                                  | What happened                                                                                                                                                                                                                                                                                                                                                                     | Where the rules live                                                                                                                                                                                           |
| ---------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Extension: capture paused with a storage warning                                         | Storage pressure: capture auto-pauses at 8 MiB of the 10 MiB quota, with an explicit keep-recording override. Actions performed while paused are not captured. Only your own actions free space.                                                                                                                                                                                  | [Persistence — storage pressure](../architecture/system/persistence.md#storage-pressure); [Extension capture — storage pressure](../architecture/application/extension/capture-principles.md#storage-pressure) |
| Desktop: uncommitted actions were gone after quitting                                    | The desktop pending buffer lives only in the running app. Quitting discards uncommitted captured actions; committed steps are already in the session file.                                                                                                                                                                                                                        | [Desktop guide — Your data](desktop-windows.md#your-data); [Persistence](../architecture/system/persistence.md#deliberately-ephemeral-state)                                                                   |
| Desktop: the app started with no projects and said it could not read your saved projects | The session file was damaged, or another program held it, so the app could not read it. The app never writes over such a file. It moved it aside and named where it is kept, or, when it could not move it, left it in place and saves nothing until you restart it.                                                                                                              | [Desktop guide — Your data](desktop-windows.md#your-data)                                                                                                                                                      |
| Extension: "Commit failed: Not the active recording"                                     | Another side panel, in another window, opened or created a project or a recording. Capture now goes to the other panel's new recording, or has stopped if a project was opened or created. **Resume**, **Clear**, re-record, and **Pause** while the other panel captures are refused the same way. A refused action changes nothing. Open the recording again to record into it. | [Extension guide — Side panels in two windows](extension.md#side-panels-in-two-windows); [Extension runtime — Panel protocol](../architecture/application/extension/runtime.md#panel-protocol)                 |
| Extension: pending actions vanished when reopening                                       | Opening or creating any recording discards the pending list, after a browser restart too, since the reopened panel starts at the projects list.                                                                                                                                                                                                                                   | [Extension guide — Pending actions](extension.md#pending-actions)                                                                                                                                              |
